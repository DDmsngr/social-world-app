# ChaWo

Соцсеть, которая становится городом: лента, живая карта места, мессенджер со звонками и каналами в одном Android-приложении. Раньше проект назывался Social World (отсюда имя репозитория и bundle id `ru.socialworld.app`). Питч-сайт — [ddmsngr.github.io/social-world](https://ddmsngr.github.io/social-world/).

Приложение раздаётся файлом (APK) мимо магазинов и обновляется само. Бэкенд — собственный сервер в Яндекс Облаке: персональные данные хранятся в РФ.

## Что умеет

Пять вкладок внизу:

| Вкладка | Что внутри |
|---|---|
| **Flow** | Лента: моменты, статьи, события, маршруты, истории. Подписки, лайки, комментарии (с эмодзи), рекомендации «Для вас». |
| **Pulse** | Карта города (Яндекс MapKit): события, места, квесты, просьбы «Мне надо», «кто рядом» с огрублённой точкой. |
| **Создать** | Публикация момента, статьи, события, **запись маршрута** (идёт в фоне, с лимитом времени), квест, «Мне надо». |
| **Чаты** | Личные чаты со сквозным шифрованием, группы, каналы, голосовые и видеозвонки, трансляция геопозиции в чат, эмодзи, закрепление, «в сети / печатает». |
| **Профиль** | Имя, @ник, город, баллы Activity Points, приглашения и реферальная программа, настройки приватности, удаление аккаунта. |

Вход — только VK ID и Яндекс ID. При первом входе — знакомство (имя, город, ник) и проводник по вкладкам. Вход по почте отключён.

## Как устроено

```
Телефон (Flutter) ──HTTPS──▶ Caddy ──▶ envoy ──▶ self-hosted Supabase
                                 │                (Postgres + PostGIS, Auth, REST,
                                 │                 Realtime, Storage, Edge Functions)
                                 ├──▶ /updates   раздача APK и манифеста обновлений
                                 └──▶ /r/<код>   страница приглашения
Звонки: WebRTC, ретранслятор coturn на том же сервере.
Push: Firebase Cloud Messaging (отправляет Edge Function push-send).
```

Всё живёт на одной виртуальной машине Яндекс Облака (домен `api-socialworld.deepdrift.tech`). **Её нельзя останавливать**: через неё идут и API, и обновления приложения. Резервный дамп базы снимается раз в сутки (хранится 7 копий), плюс снимок диска.

### Клиент

Flutter (stable), Dart `^3.12`, Riverpod 3, go_router 18. Слои в каждой фиче: `domain` (сущности и интерфейсы репозиториев, ничего не знает про Supabase и Flutter) → `data` (реализации) → `presentation` (Riverpod-провайдеры и экраны).

```

               media, network, oauth, permissions, push, router, session, share,
               shortcuts, theme, update (самообновление), widgets
  features/    auth, feed, discover, create, routes, events, quests, needs,
               stories, chat (в т.ч. live_location), calls, channels, referrals,
               points, notifications, saved, profile, moderation, migration
               (импорт из другой соцсети), assistant, invite, shell
supabase/

  tests/       SQL-проверки (запуск — supabase/tests/README.md)
```

### Бэкенд

Supabase, развёрнутый self-hosted (docker compose) на ВМ. Хостить его в РФ нужно по 152-ФЗ: персональные данные россиян, включая геолокацию, хранятся на территории страны.

Edge Functions: `oauth-vk-start/callback` и `oauth-yandex-start/callback` (вход через VK ID и Яндекс ID), `push-send` (доставка push через FCM), `chat-media-gc` (чистка удалённых вложений). По расписанию (pg_cron) работают: начисление реферальных баллов, отправка отложенных сообщений, уборка медиа, закрытие просроченных трансляций геопозиции.

Правила схемы, которые нельзя ломать:
- RLS включён на всех таблицах, по умолчанию доступ запрещён.
- Каждая новая функция: `revoke all on function … from public, anon;` и `grant execute … to authenticated;`. Анонимный доступ закрыт миграциями 0026–0028, не открывать заново.
- Права на колонки профиля выдаются поимённо (`grant update (…)`), `social_score` руками не правится.
- Колонки, которых нет в `grant update`, клиент менять не может — проверяйте это, добавляя поле в профиль.

#### Накат миграции

Миграции накатываются на сервер вручную, перед выпуском сборки, которой они нужны. Порядок: репетиция на копии базы с откатом → накат на боевую → пуш кода.

```bash
scp supabase/migrations/00NN_….sql <сервер>:/tmp/N.sql
ssh <сервер> "docker cp /tmp/N.sql supabase-db:/tmp/N.sql && \
  docker exec supabase-db psql -U postgres -d postgres -v ON_ERROR_STOP=1 -1 -f /tmp/N.sql"
```

Кириллический SQL не пропускайте через пайп PowerShell (кодировка ломает идентификаторы) — копируйте файлом. Для служебных таблиц (очистка, загрузка дампа) нужна роль `supabase_admin`.

## Запуск

```bash
cp .env.example .env     # SUPABASE_URL, SUPABASE_ANON_KEY, YANDEX_MAPKIT_API_KEY
flutter pub get
flutter run
```

Без заполненного `.env` приложение поднимается на заглушках и включает dev-режим: на экране входа появляется панель «Сразу в приложение» / «Через онбординг», код подтверждения подставляется сам. Вся dev-обвязка лежит в `lib/core/dev/` и `lib/core/config/dev_mode.dart`. Отключить панель: `--dart-define=DEV_MODE=false`.

Ключ MapKit нужен именно для сервиса «MapKit Mobile SDK» (ключ от JavaScript API или Геокодера выглядит так же, но карта с ним не грузит тайлы).

```bash
flutter analyze
flutter test
```

Веб-сборка — площадка для разработки и демо, не продукт: карта на вебе не работает (плагин MapKit её не умеет). Автоматический обход экранов со скриншотами — `tool/README.md`.

Android локально не собираем: все APK собирает CI.

## Сборка и выпуск

CI — `.github/workflows/flutter-ci.yml`. На каждый push в `main`: анализ, тесты, веб-сборка, затем release APK.

- Версия: `versionCode = 5000 + номер запуска`. Подпись постоянным ключом из секретов репозитория, поэтому обновление ставится поверх без удаления.
- Рабочая сборка — только arm64 (около 90 МБ). Универсальный APK (около 150 МБ) собирается отдельно для ссылки скачивания. В CI проверяется, что в arm64-файле нет библиотек других архитектур.
- Файлы и манифест публикуются в публичном зеркале `DDmsngr/social-world-releases` (GitHub Release) и копией на собственный сервер по sftp (`/updates/`).
- Приложение сначала смотрит на свой сервер, GitHub — запасной путь (с телефонов в РФ он открывается через раз).

### Самообновление

Приложение раз в несколько часов сверяет `manifest.json` с установленной версией. По Wi-Fi новый APK скачивается сам, после чего над вкладками появляется плашка «Установить». По мобильной сети — только если включено в «Настройки → Приложение». Установка — системное подтверждение Android. Код: `lib/core/update/`.

Секреты репозитория (значений здесь нет): ключи подписи Android, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` (публикация в каталог релизов дашборда), `YANDEX_MAPKIT_API_KEY`, `GOOGLE_SERVICES_JSON_BASE64`, токен записи в репозиторий релизов, ключ sftp для раздачи обновлений.

## Приватность и безопасность

- **Геопозиция.** Точные координаты остаются на телефоне. На карте других людей видно только размытую точку: `GeoPrivacy.blur` привязывает положение к центру ячейки (по умолчанию 500 м), сетка сдвинута на соль пользователя. История перемещений на сервере не хранится. Тесты: `test/core/location/geo_privacy_test.dart`.
- **Личные чаты** шифруются сквозным шифрованием (X25519, ключи на телефонах); сервер содержимого не видит. Точки трансляции геопозиции в личных чатах шифруются тем же ключом. Группы и каналы не шифруются.
- **Запись маршрута** идёт как служба переднего плана с видимым уведомлением, трек хранится на телефоне и уходит на сервер, только если пользователь его опубликует.
- **Аналитика** — Яндекс AppMetrica, только названия событий; геолокация и рекламный идентификатор отключены (`lib/core/analytics/analytics.dart`).
- **Удаление аккаунта** — в настройках, функция `delete_my_account` (миграция 0061).
- Описание того, какие данные обрабатываются и где хранятся, — `docs/legal/` (черновик для юриста).
