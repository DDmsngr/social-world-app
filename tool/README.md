# Прогон интерфейса в браузере

`web_flow.js` проходит приложение целиком — вход, онбординг, все четыре вкладки — и складывает скриншоты. Нужен, чтобы после правок смотреть на экраны, а не угадывать.

```bash
flutter build web
cd build/web && python -m http.server 8765 --bind 127.0.0.1

# в другом терминале
PW_ARTIFACT_DIR=D:\temp\sw-shots TARGET_URL=http://127.0.0.1:8765 \
  node <playwright-skill>/run.js tool/web_flow.js
```

## Чего это стоило выяснить

Flutter рисует интерфейс в canvas, обычные локаторы по нему не работают. Дерево доступности появляется в DOM только после клика по `flt-semantics-placeholder` — скрипт делает это первым делом.

Дальше три отдельные грабли:

- **Поля ввода.** Клик по полю Playwright не проходит: соседние semantics-ноды перекрывают его прямоугольник. Фокус ставим из JS по `aria-label`, текст шлём `keyboard.type` — тогда его забирает сам Flutter. `fill()` не годится, он пишет в DOM-инпут мимо контроллера.
- **Кнопки.** По той же причине перекрытия — обычный клик с откатом на `force: true`.
- **Вкладки.** В дереве это `tab` без названия, поэтому жмём мышью по координатам центров колонок.
