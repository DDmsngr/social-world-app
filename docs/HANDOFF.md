## 0. Правила работы с владельцем

- **Код не менять без команды.** Брейншторм = только записи. Фразы «сделай / поправь / запушь» — команда.
- **В `main` — только по явной команде.** Push в `main` запускает CI → релизный APK → автообновление у всех пользователей.
- **Миграции на сервер владелец накатывает руками** (на работе, с компьютера). Клиент обязан переживать сервер без свежих миграций — так и сделано.
- Тексты подсказок, справки, согласий пишет Claude через скилл **`/human`**. В облачной сессии такого скилла не было — подключить в боевой.
- Название продукта — **ChaWo**. В коде, README и `pubspec` пока Social World; переименование — по отдельной команде.
- Общение и коммиты — по-русски. Подпись в коммитах: `Co-Authored-By: …` и `Claude-Session: …` (строки даёт harness).
- Фото людей **не отправлять в зарубежные ИИ-сервисы** (152-ФЗ, данные должны оставаться в РФ).
- Instagram в РФ запрещён: **никакой интеграции с ним** — только инструкция и согласие (см. раздел 4.1).

### 3.4. Архитектура, которую стоит знать

- **`MessageEnvelope`** (`message_envelope.dart`): обычный текст в личных чатах по-прежнему «голая строка» (читают и старые версии). Текст с ответом/пересылкой — JSON с маркером `{"cw":1,…}`; вложения — `{"v":1,…}` + ключ `m` для meta. Тип сообщения берётся из конверта, не из открытой колонки `kind`.
- **`liveFeed`** (`live_feed.dart`): чистая функция с внедряемыми зависимостями — реалтайм + опрос + дедупликация по подписи + склейка пачек + самолечение контекста. 9 тестов.
- **`messageActions`** / **`canDeleteForEveryone`** — одно место с правилами меню; сервер проверяет то же самое.
- **Совместимость с несвежим сервером**: нет колонок `meta/silent` (PGRST204) → сообщение уходит без них; нет таблицы отложенных → `ChatFeatureUnavailable` («пока недоступно»); нет `delete_chat_messages` → `ChatDeleteUnavailable`; push-send не падает без колонки `silent`.
- Riverpod 3 по умолчанию **автоповторяет** упавшие провайдеры (это и показывало спиннер). Для `messagesProvider` и `scheduledMessagesProvider` отключено: `retry: (_, _) => null`.

## 4. Планы (не реализовано) и принятые решения

### 4.1. Перенос из Instagram, календарь фото, гео — `instagram-import-photo-calendar-geo.md`

**Решения:**
- Перенос — **из архива, который человек получает сам** («Скачать информацию», JSON). Экран-инструкция **без** ссылок в Instagram, без встроенного браузера, без брендинга/логотипов; про VPN и обход блокировок не писать вообще.
- Перед разбором архива — **экран согласия** (черновик из 7 пунктов в документе, версионируется, в базе `import_consents`). Перенесённое по умолчанию «Только мне», место скрыто.
- **Истории переносим** (из архива) как воспоминания в календаре, не в ленту.
- **Галерея телефона — только по запросу пользователя**, сами не предлагаем.
- У поста три времени: `taken_at` (снято), `published_at` (опубликовано), `created_at`. Календарь по `taken_at` с учётом часового пояса.
- Гео: **4 уровня видимости** (никому / город / район / точно). Автор всегда видит точную точку на своей карте. Блок «Место снимка» на виду над «Опубликовать», не в свёрнутой панели. Глобально: «Никогда не показывать место другим» (проверяет сервер), «Не сохранять место снимка», «Скрыть у всех постов сейчас», «Удалить все точки».

**Ждёт решения:** где хранить точную точку — A (таблица «только автор», рекомендовано) / B (только на устройстве) / C (зашифрованно).

### 4.2. Знакомство с приложением — `app-tour-hints.md`

- Подсказки появляются **в момент нужды**, одна за раз, можно закрыть, не показываются если действие уже сделано.
- **Приветственная карточка с выбором** «Показывать подсказки?». При «Нет» остаются **обязательные подсказки про гео** (своя точка на карте, место при первой публикации).
- **Вход по QR места**: понять зачем пришёл → авторизация → **бонус первым** → потом онбординг и карточка подсказок.
- **Справка — строго внутри приложения**, плюс «Показать подсказки заново». Прочитанные подсказки хранить в профиле на сервере.
- **Экран лицензий открытого ПО** — свой, в стиле ChaWo, спрятан в «Настройки → О приложении → Лицензии» (юридически обязателен, удалять нельзя; то же сделать в КОТТ).

### 4.3. Чат: что ещё не сделано — `chat-message-menu.md`

- **Реакции** (решено «да»): ряд из 6 над меню, двойной тап = ❤️, чипы под сообщением, одна реакция на человека, таблица `chat_reactions`. В личных чатах предлагается хранить **открыто** (метаданные) — ждёт согласия.
- «Все медиа чата», «Изменить» сообщение, «Пожаловаться» (нужен `message` в `report_target` и согласие на передачу расшифрованного текста модератору).
- Отложенные: «отправить сейчас», перенос времени, отложенные вложения.
- «Удалить у всех» — без ограничения по времени; заглушку «Сообщение удалено» **не** показываем (решено).

### 4.4. Уведомления в чатах — `chat-notifications.md`

Быстрые настройки из шторки в чате (колокольчик): со звуком / только вибрация / тихо / выключить; «выключить на 1 ч / 8 ч / до утра / 1 день»; расписания «рабочее время», «кроме ночи»; упоминания пробивают; общие настройки по типам чатов; 🔕 в списке. **Решение принимает сервер** (`push-send`), потому что пуш в фоне рисует система. Звук/вибрация — отдельные каналы Android (`messages` уже есть, `messages_silent` теперь тоже). Ждёт ответов на 4 вопроса (раздел 7). Заготовка под этот план частично уже есть: канал и флаг `silent`.

### 4.5. Стикеры и магазин — `stickers.md`

- Эмодзи-«стикеры» убраны. Будут **настоящие стикеры** (WebP 512×512 с альфой; Lottie и видео позже).
- **Фирменные паки — только от нашего дизайнера**, вшиты в приложение; флаг `is_official` ставится вручную.
- **Свои стикеры, как в Telegram**: фото → вырезание фона на устройстве (ML Kit / Vision) → подпись → эмодзи → пак.
- **«Кто может установить» пак**: только я / взаимные подписки / подписчики / по ссылке / все (магазин). Сузили доступ — **пак пропадает** у тех, кто больше не подходит; стикеры в старых сообщениях остаются.
- **Магазин паков**: фирменные, тренды недели (затухание, защита от накрутки), новое, «Сочи и рядом», подборки, категории, поиск.
- **Модерация**: **ИИ проверяет каждый стикер**; чисто → сразу в магазин; явное нарушение → отказ с причиной; сомнительное → к человеку (предложение, ждёт подтверждения). **Жалобы — человеку**; N жалоб от разных людей снимают пак до решения. ИИ — только российское облако или своя модель на нашем сервере (152-ФЗ).
- **Платные паки — после 1 000 000 пользователей.**

## 5. Риски и срочное

1. **Возможная утечка GPS через EXIF.** Фото уходят в публичный бакет «как есть» (`media_uploader.dart`). Если `image_picker` на Android сохраняет EXIF при сжатии — а, по нашему пониманию, сохраняет — то галочка «скрыть место» не защищает координаты в самом файле. **Не проверено на устройстве** — проверить и, если подтвердится, чистить метаданные перед загрузкой. Это нужно сделать раньше фич с гео.
2. **Корень зависаний не доказан** — по коду он вероятен (мёртвые сокеты после смены сети/VPN, нет тайм-аутов, автоповтор Riverpod → спиннер), закрыт сразу по нескольким причинам, но подтвердится только на телефоне.
3. **«Когда будет в сети»** зависит от новой версии у собеседника и от `pg_cron`; без любого из них сообщение ждёт (до 14 дней), не теряется.
4. **Доступа к реальной базе из облачной сессии нет** — «посмотреть сигналы» по данным нельзя; помогает только SQL-запрос, который выполняет владелец.

## 6. Технические заметки и грабли

**Окружение**
- Flutter stable (в облаке ставился клоном в scratchpad, версия 3.47.5), Dart 3.12. После каждого запуска flutter **сам правит `analysis_options.yaml`** — откатывать `git checkout analysis_options.yaml`.
- **Не запускать `dart format lib test`** целиком: репозиторий не форматирован этим форматтером, правит ~136 чужих файлов. Форматировать только свои файлы.
- Тесты: `flutter test` (все), `flutter test test/features/chat` (чат), `supabase/tests/run.sh` (SQL; нужен обычный PostgreSQL, `PGHOST/PGPORT/PGUSER`). Postgres не стартует от root — запускать от пользователя `postgres`.

**Flutter**
- `Scaffold.bottomNavigationBar`: чтобы скрыть панель — **`null`**, не `SizedBox.shrink()` (иначе тело теряет нижний отступ и поле ввода уезжает под системные кнопки). Есть регрессионный тест.
- `IconButton(tooltip: …)` спорит с долгим тапом (у Tooltip свой long-press): у кнопки «Отправить» tooltip убран, доступность — через `Semantics` + `customSemanticsActions`.
- В `Stack` для сообщения нужен `StackFit.passthrough`, иначе пузырь теряет ширину и «уезжает» к краю.
- `ChatComposer` сбрасывает `chatEmojiPanelOpen` после кадра (в `dispose` дерево заблокировано).

**Тесты виджетов**
- Лист/диалог открывается за два кадра: `pump()` + `pump(500ms)`; одного `pump(400ms)` мало.
- `pumpAndSettle` может не дождаться покоя при фоновых таймерах — считать кадры явно.
- Реальные потоки заглушки — через `tester.runAsync`.

**Сервер**
- Все миграции проверены только на заглушках Supabase; `pg_cron` в проверке отсутствует (проверяется сама функция выпуска).
- Edge Function деплоится вручную; `deno` в облачной сессии нет — TypeScript не прогонялся, правка `push-send` небольшая и проверена глазами.
