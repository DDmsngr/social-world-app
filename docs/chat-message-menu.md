# Чаты: меню сообщения, удаление, действия с медиа

План реализации (30.09). Кода пока нет, делать только по команде.

Референс — меню медиа в Telegram (скриншот от 30.09): сохранить в галерею, рисунок, сканировать QR, извлечь текст, все медиа, показать в чате, создать стикер, ответить, поделиться, изменить и переслать, удалить.

---

## 0. Что есть сейчас

- `MessageBubble` (`lib/features/chat/presentation/widgets/message_bubble.dart`) не реагирует ни на долгий тап, ни на свайп.
- Фото из чата открываются в общем `PhotoViewer` (`lib/core/media/photo_viewer.dart`), где есть только крестик. Видео открывается в `VideoFullScreen`.
- В `ChatRepository` нет ни удаления, ни правки, ни ответа.
- В базе на `chat_messages` выдано только `select, insert`. Политик `update` и `delete` нет, удалить сообщение нельзя даже через API.
- Лента сообщений приходит через `.stream(primaryKey: ['id'])`, то есть через Supabase Realtime. Удаление строки само придёт собеседнику, и сообщение пропадёт из потока.
- Последнее сообщение в списке чатов считает `my_chats()` запросом «последнее по `sent_at`». После удаления превью само покажет предыдущее сообщение.
- Личные чаты зашифрованы (E2E). Сервер видит только шифротекст, файлы в `chat-media` тоже зашифрованы. Отсюда ограничения для пересылки и правки (раздел 3).
- Тесты: в `test/features/chat/` сейчас только `chat_crypto_service_test.dart`.

## 1. Анализ юзабилити меню Telegram (по скриншоту)

| Что видим | Проблема | Как делаем у нас |
|---|---|---|
| 12 пунктов в одном списке | Взгляд не цепляется, нужное ищешь. Больше 7 пунктов — перегруз | Максимум 6–7, остальное прячем в «Ещё» или вообще не делаем |
| «Удалить» внизу, сразу под «Изменить и переслать», того же цвета | Легко промахнуться, разрушительное действие не выделено | «Удалить» красным, отделено линией, всегда последним |
| Смешаны действия с сообщением (ответить, переслать) и с картинкой (рисунок, QR, текст) | Непонятно, что к чему относится | Две группы: «с сообщением» и «с файлом» |
| Редкие пункты («Рисунок», «Создать стикер») стоят выше частых («Ответить») | Частое приходится искать | Сверху самые частые: Ответить, Сохранить, Переслать |
| Меню закрывает всю картинку | Не видно, с чем работаешь | Нижний лист (bottom sheet) на половину экрана, картинка видна сверху |
| Долгий тап никак не подсказан | Новичок не узнает, что меню есть | Подсказка при первом открытии чата (система подсказок из `app-tour-hints.md`) и свайп вправо для ответа |

**Предложения по делу:**

1. **Одно меню на все типы сообщений, пункты зависят от типа.** Человек учит один жест: долгий тап. Для медиа в просмотрщике — те же пункты под «⋮».
2. **Удаление в два режима, как принято в мессенджерах:** «Удалить у меня» и «Удалить у всех». Второй вариант доступен только для своих сообщений.
3. **«Удалить у меня» можно отменить.** Внизу 5 секунд висит «Сообщение удалено · Отменить», без диалога: действие обратимо, лишний вопрос раздражает. «Удалить у всех» необратимо, поэтому перед ним диалог.
4. **Отклик на долгий тап:** лёгкая вибрация, выбранное сообщение подсвечивается, остальное затемняется.
5. **Свайп вправо — ответ.** Это самое частое действие, и лезть за ним в меню не надо.
6. **Доступность.** Все пункты меню дублируются как `Semantics.customActions`, чтобы в TalkBack/VoiceOver они были доступны без долгого тапа.
7. **Не делаем** «Рисунок», «Создать стикер» и «Извлечь текст». Первые два — редкие и дорогие в реализации. Для третьего офлайн-распознавание ML Kit, насколько я знаю, не поддерживает кириллицу (проверить), а в Android 14+ и iOS выделение текста на картинке уже есть в системе.

### 2.3. Диалог удаления

- **Своё сообщение:**
  > Удалить сообщение?
  > ☑ Удалить и у <имя> *(в группе — «у всех»)*
  > [Отмена] [Удалить]

  Галочка включена по умолчанию: удаляя своё, человек почти всегда хочет убрать его у собеседника.

- **Чужое в группе, если я владелец группы:** тот же диалог с галочкой «Удалить у всех». Это модерация.
- **Несколько выбранных:** «Удалить 5 сообщений?». Галочка «у всех» доступна, только если все выбранные мои (или я владелец группы).

## 3. Логика и данные

### 3.1. Удаление у всех — жёсткое

- Строка удаляется из `chat_messages`, файл — из `chat-media`.
- Почему не «мягкое» удаление с пометкой: у личных чатов сервер и так не видит содержимое. Держать шифротекст удалённого сообщения незачем, а меньше данных — меньше рисков (152-ФЗ).
- Заглушку «Сообщение удалено» не показываем (так делает Telegram). *Открытый вопрос: WhatsApp её показывает — решить.*

**Миграция `0033_chat_message_delete.sql`:**

```sql
-- Удаление у всех: только через функцию, прямого delete на таблицу не даём.
create function delete_chat_messages(in_ids uuid[])
returns table (id uuid, media_path text)
language plpgsql security definer set search_path = public as $$
begin
  return query
  delete from chat_messages m
  where m.id = any(in_ids)
    and (
      m.sender_id = auth.uid()
      or exists (   -- владелец группы удаляет любое в своей группе
        select 1 from chat_members me
        join chat_conversations c on c.id = me.conversation_id
        where me.conversation_id = m.conversation_id
          and me.profile_id = auth.uid()
          and me.role = 'owner'
          and c.direct_key is null
      )
    )
  returning m.id, m.media->>'path';
end $$;
```

- Функция возвращает удалённые id. Если вернулось меньше, чем просили, клиент показывает «Часть сообщений удалить нельзя».
- **Путь файла в личных чатах лежит внутри шифротекста**, сервер его не знает. Поэтому файл удаляет клиент: он знает `attachment.path` после расшифровки. Нужна политика `storage.objects for delete`: удалять можно только объекты своей папки-чата, которые загрузил сам (`owner = auth.uid()`).
- *Проверить:* у realtime-события DELETE при включённом RLS приходит только первичный ключ. Для `.stream()` этого хватает.
- Ограничение по времени для «удалить у всех» — **открытый вопрос** (Telegram — без ограничения, WhatsApp — около 2 суток). Предлагаю без ограничения.
- Чужое сообщение в **личном** чате удалить у всех нельзя: это переписка собеседника.

### 3.2. Удаление у меня

- Таблица `chat_hidden_messages (profile_id, message_id, hidden_at)`, pk `(profile_id, message_id)`. RLS: только своё.
- `watchMessages` фильтрует скрытые на клиенте: список скрытых грузится при открытии чата и обновляется при скрытии. Realtime `.stream()` не умеет join, поэтому фильтр делаем после.
- `my_chats()` при подсчёте последнего сообщения и непрочитанных тоже пропускает скрытые: `not exists (select 1 from chat_hidden_messages ...)`.
- «Отменить» в течение 5 секунд удаляет запись из `chat_hidden_messages`. До истечения 5 секунд запрос на сервер можно вообще не отправлять.
- Кэш файлов на устройстве (`ChatMediaCache`) при скрытии чистится для этого сообщения.

### 3.3. Изменения в `ChatRepository`

```dart
/// Удалить у всех. Возвращает id, которые удалось удалить.
Future<Set<String>> deleteForEveryone(List<ChatMessage> messages);

/// Скрыть у себя. Обратимо через [unhide].
Future<void> hideForMe(List<ChatMessage> messages);
Future<void> unhide(List<ChatMessage> messages);

/// Файл вложения в галерею телефона (расшифрованный).
Future<void> saveToGallery(ChatMessage message);
```

- «Копировать» и «Поделиться» живут в презентации: `Clipboard.setData` и `share_plus` (уже в `pubspec.yaml`) с файлом из `attachmentFile()`.
- `saveToGallery` — пакет `gal` (Android/iOS, сохраняет фото и видео, сам спрашивает разрешение). **Новая зависимость — согласовать.**
- `LocalChatRepository` (dev-режим) реализует то же в памяти, чтобы меню можно было проверить без бэкенда.

### 3.4. Права — одна функция

`MessageActions.available(message, {mine, isOwner, isDirect, closed, now})` возвращает список пунктов. Это чистая функция в `domain`, без Flutter, на неё пишутся юнит-тесты. Меню, просмотрщик и `Semantics` берут пункты оттуда, поэтому правила живут в одном месте.

### 3.5. Этапы 2–3 (кратко, детали — перед началом этапа)

- **Ответить:** колонка `reply_to uuid` (метаданные, не содержимое, — допустимо открыто). Цитату клиент берёт из уже расшифрованного сообщения у себя. Плюс свайп вправо.
- **Изменить:** в личных чатах — новое зашифрованное содержимое с той же подписью и `edited_at`. Нужна отдельная политика `update` только на шифро-колонки и только для своих сообщений не старше 48 ч.
- **Переслать** в личный чат: файл скачать, расшифровать, **зашифровать новым ключом** и загрузить заново. Ссылку на чужой зашифрованный файл переслать нельзя, у получателя не будет ключа.
- **Пожаловаться:** в `report_target` нет `message`. Добавить его в enum, а в жалобу класть **расшифрованный текст** с согласия жалующегося: иначе модератор E2E-сообщение не прочитает.
- **Все медиа чата:** сетка по `kind in (image, video)`. В личных чатах тип виден серверу, а превью приходится расшифровывать на клиенте, поэтому грузим постранично.

## 8. Поле ввода и навигация в чате (30.09, по скриншотам)

### 8.1. Баг: смайлик улетает отдельным сообщением

> **Решение (30.09):** нынешние «стикеры»-эмодзи **убираем**. 🙂 открывает только эмодзи, которые вставляются в текст. Настоящие стикеры (фирменный пак ChaWo + свои, как в Telegram) — отдельный план `docs/stickers.md`. Ниже — исходный разбор; вкладка «Стикеры» появится уже с новыми стикерами.

**Причина (по коду):** кнопка 🙂 слева от поля — это не эмодзи, а выбор **стикеров** (`_pickSticker` → `showStickerPicker`). Тап по смайлику сразу отправляет его отдельным сообщением `kind = sticker`, крупно, без пузыря. Текст в поле при этом не трогается. Человек ждёт, что смайлик встанет в текст, а он «улетает».

**Как исправить:**
- Кнопка 🙂 открывает **панель вместо клавиатуры** с двумя вкладками: **«Эмодзи» | «Стикеры»**.
- **Эмодзи** вставляются в текст **в позицию курсора** и ничего не отправляют. Есть «Недавние» и поиск.
- **Стикеры** отправляются сразу, как сейчас. Это ожидаемо: вкладка называется «Стикеры».
- Кнопка переключается 🙂 ↔ ⌨️, чтобы вернуться к клавиатуре.
- Если в поле уже набран текст, а человек тапнул стикер, текст остаётся в поле (не теряем).
- Пакет: `emoji_picker_flutter` (готовая панель с категориями, недавними и поиском) — **новая зависимость, согласовать**. Или своя панель на базе текущих паков из `sticker_picker.dart`.
- Тест: тап по эмодзи → символ в `TextEditingController` на месте курсора, `send` не вызван; тап по стикеру → `send(kind: sticker)` вызван, текст в поле сохранился.

### 8.2. Поле ввода маленькое — должно расти

Сейчас: `minLines: 1`, `maxLines: 5`, маленькие отступы.

Как надо (по образцу поля ввода в Claude):
- **Выше в покое:** минимальная высота ~52 px, крупнее шрифт (16) и отступы.
- **Растёт с текстом** до ~40% высоты экрана над клавиатурой (≈8–10 строк), дальше прокрутка внутри поля.
- **Кнопки 🙂 и 📎 прижаты к низу** поля, когда оно выросло (как и сейчас, `CrossAxisAlignment.end`); кнопка отправки тоже внизу справа.
- **Рост плавный** (`AnimatedSize`), без прыжков.
