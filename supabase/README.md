# Бэкенд

Supabase, развёрнутый self-hosted на виртуалке в Yandex Cloud. Облачный Supabase не подходит: его сервера в США и Европе, а с 1 июля 2025 года 152-ФЗ требует хранить персональные данные россиян — включая геолокацию — на территории РФ.

Код и API при этом те же самые, меняется только площадка.

## Поднять сервер

```bash
# на VM в Yandex Cloud (Ubuntu 22.04, 2 vCPU / 4 ГБ — хватает на пилот)
git clone --depth 1 https://github.com/supabase/supabase
cd supabase/docker
cp .env.example .env
# поменять POSTGRES_PASSWORD, JWT_SECRET, ANON_KEY, SERVICE_ROLE_KEY,
# DASHBOARD_USERNAME, DASHBOARD_PASSWORD
docker compose up -d
```

Дальше — домен, сертификат Let's Encrypt и прокси на порт Kong. Обычный HTTPS/TLS, лицензия ФСБ для него не нужна: это встроенный криптокомпонент, выведенный из-под лицензирования постановлением № 313.

## Применить схему

```bash
psql "$DATABASE_URL" -f migrations/0001_init.sql
```

Нужно расширение `postgis` — в официальном образе Supabase оно уже есть.

## Что заложено в схеме

- RLS включён на всех таблицах, политика по умолчанию — запрет.
- `locations` хранит одну строку на пользователя: только размытую точку и радиус размытия. Истории перемещений нет — её незачем защищать и нечего терять.
- Чужие точки отдаёт единственная функция `nearby_profiles`, с ограничением по радиусу (максимум 10 км), по свежести (2 часа) и по количеству.
- `social_score` в профиле — производная от лога `score_events`, руками не правится.
- `reports` пишет любой авторизованный, читает только свои — очередь модерации разбирается отдельным сервисным доступом.

## Ключи

`ANON_KEY` и URL кладутся в `.env` приложения (см. `.env.example` в корне). `SERVICE_ROLE_KEY` в приложение не попадает никогда — только серверные задачи.
